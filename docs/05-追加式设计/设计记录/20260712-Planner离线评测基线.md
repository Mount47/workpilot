# Planner 离线评测基线

## 基本信息

- 日期：2026-07-12
- 状态：已完成
- 关联模块：Evaluation、Planning、Provider Contract、CLI

## 目标

建立不依赖真实 API Key 的 Planner 回归评测。每个案例提供结构化 PlanDraft 或标准化 Provider 错误，并通过真实 ConstrainedLLMPlanner、PlanValidator、RuntimePlanPolicy 和 FallbackPlanner 执行。

## 指标

- decision_accuracy：LLM、deterministic、failed 选择是否符合预期；
- plan_validity_rate：最终返回计划通过验证的比例；
- llm_acceptance_rate：模型草稿被接受的比例；
- fallback_rate：确定性降级比例；
- failure_rate：不可降级错误比例；
- unsafe_acceptance_rate：预期应拒绝或降级的草稿被 LLM 路径接受的比例；
- average_input_tokens / average_output_tokens；
- average_latency_ms。

## 安全边界

- 静态 Provider 只用于离线评测，不进入生产 Registry；
- 报告不保存 Prompt、API Key 或模型响应正文；
- authentication 案例必须失败，不能被降级掩盖；
- invalid_response、瞬时错误和非法计划按既定策略评测；
- 该基线只证明控制逻辑可复现，不代表真实模型质量。

## 交付

- PlannerEvalCase、PlannerEvalSuite 和 PlannerEvalReport；
- PlannerEvalRunner；
- `workpilot planner-eval`；
- 最小 Planner 基线 JSON；
- 自动化测试、中文实现文档和状态更新。

## 实际结果

- PlannerEvalCase 强制每个案例只能提供 PlanDraft 或 Provider Error 之一；
- StaticPlannerEvalProvider 未进入生产 Registry；
- PlannerEvalRunner 复用真实 Planner 验证和降级栈；
- CLI 输出摘要并生成 `planner_eval_report.json`；
- 五个最小案例的 Decision Accuracy 为 100%、Plan Validity 为 80%、Fallback 为 60%、Unsafe Acceptance 为 0%；
- 完整回归为 101 passed、总体覆盖率约 89%。

## 遗留限制

- 静态 Provider 不模拟真实模型内容分布和随机性；
- 瞬时调用失败通常没有 Usage，因此失败调用 Token 和成本无法精确统计；
- 尚无真实 Provider 的 Planner 质量、成本与延迟对比；
- 尚未把 Planner 指标与最终任务完成质量关联。
