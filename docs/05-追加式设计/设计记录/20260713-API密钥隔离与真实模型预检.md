# API 密钥隔离与真实模型预检

## 基本信息

- 日期：2026-07-13
- 状态：设计已确认，开发中
- 关联模块：Settings、Provider Registry、Provider Adapter、CLI、Route Config

## 背景

WorkPilot 已支持 OpenAI、Claude、DeepSeek、Qwen、百炼、GLM、Gemini 和自定义兼容网关，但真实模型运行前缺少统一离线预检。

当前 OpenAI-compatible Adapter 还存在跨厂商环境变量兜底：未显式传入 Key 时会依次尝试多个 Provider 的 Key。这可能把一个厂商的凭据发送到另一个 endpoint，必须在真实调用前移除。

## 目标

1. 每个 Provider 只读取自己声明的环境变量；
2. Provider Registry 是密钥映射的唯一入口；
3. 缺失 Key 时在 SDK Client 创建前明确失败；
4. 新增完全离线的 `workpilot doctor` 命令；
5. Doctor 检查 Provider、Model、Base URL、能力和 Key 是否配置；
6. Doctor 只输出布尔状态和环境变量名，永不输出 Key；
7. Route Config 可以一次预检所有主备目标；
8. 不发送网络请求，不产生 Token 费用。

## 密钥映射

```text
openai   -> OPENAI_API_KEY
claude   -> ANTHROPIC_API_KEY
deepseek -> DEEPSEEK_API_KEY
qwen     -> DASHSCOPE_API_KEY
bailian  -> DASHSCOPE_API_KEY
glm      -> GLM_API_KEY
gemini   -> GEMINI_API_KEY
custom   -> CUSTOM_API_KEY
```

Stub 不需要 Key。

## 安全规则

- 禁止 OpenAI-compatible Adapter 在多个环境变量之间猜测；
- 禁止把 Key 放入 CLI 参数、Route JSON、Trace 和异常消息；
- `.env` 和 `.env.local` 必须被 Git 忽略；
- `.env.example` 只能包含空值和说明；
- Route Config 只允许 Provider、Model、Tier 和能力要求；
- Base URL 输出前移除用户信息、查询参数和 fragment；
- URL 中包含 userinfo、query 或 fragment 时预检失败；
- 非 Stub Provider 缺 Key 时 fail closed。

## Doctor 输出

单 Provider：

```text
Provider: deepseek
Transport: openai_compatible
Model: <configured model>
Base URL: https://api.deepseek.com
API key env: DEEPSEEK_API_KEY
API key configured: yes | no
Structured output: validated_json
Ready: yes | no
```

Route Config：按 task_type 和 target 顺序显示，每个目标独立检查，并给出总 Ready 状态。

Doctor 不实例化 SDK Client，也不验证远端 Key 是否有效。远端认证只能在用户明确发起真实评测时验证。

## 配置错误

统一 `ProviderConfigurationError`，覆盖：

- unknown_provider；
- missing_api_key；
- missing_model；
- missing_base_url；
- unsafe_base_url。

错误消息可以包含 Provider 名和应配置的环境变量名，不能包含 Key 值。

## 最小真实评测门槛

只有以下条件满足后才建议真实调用：

- `workpilot doctor` 返回 Ready；
- 离线 121+ 测试通过；
- Stub Eval 和 Planner Eval 通过；
- 使用脱敏 sample workspace；
- Token Budget 设置为小值；
- 第一轮只使用一个 Provider，不启用多 Provider Failover；
- 输出目录与 Trace 已确认不含密钥。

## 分阶段实施

### 第一阶段：密钥隔离

- Settings 暴露 Provider 对应环境变量名；
- Registry 严格校验 Key；
- Adapter 移除跨厂商 Key 猜测；
- 配置错误类型。

### 第二阶段：离线预检

- ProviderPreflightResult；
- 单 Provider 检查；
- Route Config 检查；
- `workpilot doctor` CLI；
- 脱敏输出测试。

### 第三阶段：真实模型小流量评测

- 单 Provider 单案例；
- 设置较低 Token Budget；
- 记录效果、延迟、Token 和失败类型；
- 确认后再启用任务路由和 Failover。

## 非目标

- Doctor 不发送测试请求；
- 不在代码或文档中保存真实 Key；
- 不自动修改用户 `.env`；
- 不替用户选择或购买模型服务；
- 不把“环境变量存在”解释为“远端 Key 有效”。

## 验收标准

- 错误厂商的 Key 不能被其他 Provider 使用；
- 缺 Key 时 get_provider 在 Client 创建前失败；
- Doctor 单 Provider 和 Route Config 均可离线运行；
- Doctor 输出、异常和测试日志不包含 Key；
- 自定义 Gateway 缺 Model/Base URL 时明确失败；
- 不安全 Base URL 被拒绝；
- Stub 不需要 Key且始终可以离线就绪；
- 完整回归和离线评测保持通过。

## 当前限制

- Doctor 只能证明本地配置完整；
- 模型名称和账号权限仍需远端请求验证；
- 尚未实现独立的低成本远端 health check；
- 尚未形成真实模型质量与成本基线。
