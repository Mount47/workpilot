# Provider 运行策略与任务路由

## 基本信息

- 日期：2026-07-12
- 状态：已完成
- 关联模块：Provider、Runtime、ExecutionBudget、Trace、Evaluation

## 背景

WorkPilot 已经能够通过统一 Registry 创建 Claude、OpenAI-compatible、Gemini 和企业自建 Provider，但“能够创建”不等于“能够稳定运行”。当前缺少统一的调用重试、按任务选择模型、故障转移、Prompt/Schema 版本追踪和跨模型契约测试。

## 目标

1. 对限流、超时、网络和服务端错误执行有界重试；
2. 每次尝试前检查 Run 的时间与 Token 预算；
3. 按任务类型、能力要求和模型档位选择 Provider；
4. 仅在显式 Route 允许时切换备用模型，禁止静默质量降级；
5. Trace 记录任务类型、模型选择、重试、故障转移、Prompt 和 Schema 版本；
6. 不依赖真实 API Key 完成契约回归。

## 非目标

- 本阶段不实现自动学习路由；
- 不根据厂商公开榜单直接决定生产默认模型；
- 不实现熔断器和跨进程限流；
- 不把结构化响应解析失败和网络重试混为同一种重试；
- 不在 Trace 中保存完整 Prompt、API Key 或业务正文。

## 分层设计

### RetryPolicy

RetryPolicy 只捕获统一的 `ProviderCallError`。`rate_limit`、`timeout`、`network` 和 `server` 可以重试；认证失败、非法响应和未知错误默认不重试。

每次重试遵守：

- 最大尝试次数；
- 指数退避和最大等待时间；
- 尝试前预算检查；
- 可注入 Sleep，保证测试不真实等待；
- 通过回调输出不含响应正文的 RetryEvent。

Provider 内部因 JSON/Pydantic 校验失败进行的有限修正属于 Response Validation Retry，和 Transport Retry 分开计数。

### TaskType 与 ModelRoute

初始任务类型：

- `evidence_extraction`：证据抽取；
- `planning`：结构化规划；
- `analysis`：Claim 和风险分析；
- `revision`：验证失败后的定向修订；
- `semantic_verification`：分析性结论语义复核。

Route 包含主目标、备用目标、最低模型档位、所需能力以及是否允许故障转移。模型档位仅表达 WorkPilot 内部路由策略，不宣称厂商模型的绝对能力排名。

### 故障转移规则

- 只有 Route 显式配置备用目标时才允许切换；
- 备用目标必须满足最低档位和能力要求；
- 高风险任务默认禁止降到更低档位；
- 认证或配置错误应直接暴露，不能用备用模型掩盖部署错误；
- 所有切换都必须进入 Trace。

### Prompt 与 Schema 版本

模型调用记录稳定标识，不记录正文：

```text
task_type
prompt_version
schema_name
schema_version
provider
model
route_target_index
attempt
```

## 验收标准

- RetryPolicy 对可重试和不可重试错误行为明确；
- 预算检查在每次物理尝试前执行；
- Router 能拒绝能力不足或低于最低档位的目标；
- 备用模型切换有显式事件；
- Runtime 的模型调用事件带任务和版本元数据；
- Mock 契约覆盖限流、超时、认证、非法 JSON 和主备切换；
- 全量测试和最小 Stub 评测通过。

## 实际结果

- RetryPolicy 已实现最多尝试次数、指数退避、等待上限、预算前置检查和可测试 Sleep；
- ModelRoute 已实现任务类型、内部档位、能力要求、最低档位和显式 Failover；
- TaskRoutedProvider 已为 Evidence、Analysis 和 Revision 提供 Runtime 路由；
- 模型成功调用与路由决策已经进入 Trace，未保存 Prompt 正文；
- JSON Route Config 使用 schema version 1.0，额外字段会被拒绝，示例不含 API Key；
- 完整回归为 87 passed、总体覆盖率约 89%；
- 最小 Stub Eval 保持通过。

## 遗留限制

- `planning` 和 `semantic_verification` Route 已可配置，但尚未进入对应动态主链路；
- 物理调用失败通常没有可用 Token Usage，因此失败调用成本暂时无法精确累计；
- 尚无熔断器、跨进程限流、版本化价格表和真实 Provider 质量矩阵；
- Prompt 当前只有稳定版本标识，还没有独立 Prompt Registry 和内容 Hash。
