# 统一工具协议与调用追踪

## 基本信息

- 日期：2026-07-12
- 状态：实施中
- 关联模块：Tool Registry、PlanValidator、PlanExecutor、Runtime、Trace

## 背景

当前 Tool Registry 只保存 ToolSpec，Runtime 仍按步骤名称调用内部闭包。PlanStep.inputs 没有参数 Schema，工具结果也没有统一状态和摘要，因此无法安全放宽动态计划，更无法形成一致的 tool_call Trace。

## 目标

1. ToolSpec 增加稳定版本；
2. 每个工具注册 Pydantic Input Model；
3. PlanValidator 在执行前校验 PlanStep.inputs；
4. ToolHandler 统一执行入口；
5. ToolResult 分离内部 output 与安全 output_summary；
6. Runtime 六个工具通过 Registry 绑定 Handler；
7. Trace 记录 started、completed、failed，不记录完整业务输出；
8. 保持 PlanExecutor 的依赖、重入和失败状态语义。

## 安全规则

- Input Model 默认 `extra=forbid`；
- 未注册、未绑定和参数非法均 fail closed；
- ToolResult.output 仅供同一 Run 内部传递，不进入 Trace；
- Trace 只记录工具名、版本、输入字段名、摘要、耗时和错误类型；
- Handler 异常不能转换为成功结果；
- 当前工具均为进程内 Handler，不允许任意代码执行。

## 分阶段实施

### 第一阶段：协议与输入校验

- ToolInput；
- ToolResult；
- ToolHandler / CallableToolHandler；
- Registry 保存 Spec、Input Model 和 Handler；
- PlanValidator 参数校验。

### 第二阶段：Runtime 绑定

- 将 workspace.scan 等六个闭包绑定为 Handler；
- PlanExecutor 通过 Registry.invoke 调用；
- 输出统一 ToolResult。

### 第三阶段：Trace 与调度准备

- tool_call_started / completed / failed；
- Handler 版本进入 Trace；
- 为后续拓扑调度提供统一执行边界。

## 非目标

- 本阶段不实现并行 DAG；
- 不实现远程工具协议；
- 不实现 Tool Sandbox；
- 不允许 LLM 动态注册工具；
- 不把内部对象序列化到 Trace。
