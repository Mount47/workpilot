# Claim 与实体投影解耦

## 元信息

- 日期：2026-07-15
- 状态：实验实现，多轮真实回归中，默认关闭
- 关联 Bad Case：BC-014、BC-015、BC-016、BC-017
- 关联模块：ClaimBuilder、EntityBuilder、Runtime、EntityFieldVerifier

## 问题

原链路让一次 ClaimBuilder 调用同时完成事实抽取、Claim 分类、行动/风险发现、字段填充、跨 Evidence 合并和风险去重。BC-014 Prompt 增强后，Risk Mitigation Recall 提升到 100%，但 Action Recall、Due Date Recall 和 Risk Precision 同时下降。

这不是 Schema 合法性问题。输出能够通过字段证据验证，却仍可能漏掉实体或把同一风险重复投影，说明 Claim 支持率和字段支持率不能替代实体级 Precision/Recall。

## 决策

采用两阶段分析边界：

```text
Evidence
  → ClaimBuilder：不可变事实与证据引用
  → EntityBuilder：ActionItem/Risk 业务投影
  → EntityFieldVerifier：确定性字段支持验证
  → Artifact
```

Claim 是审计事实层，Entity 是面向项目管理查询和后续长期记忆的业务视图。EntityBuilder 只能引用现有 Claim/Evidence，实体 description 始终取 Claim text，不能生成新的事实正文。

## 输入输出约束

EntityBuilder 输入完整 Claim 列表和当前 EvidenceStore，输出扁平 `EntityProjectionDraft`：

- Action：claim_id、owner、due_date_text、status 及字段 refs；
- Risk：claim_id、owner、severity、status、mitigation 及字段 refs；
- 同一种实体不得重复使用同一个 claim_id；
- 字段 refs 自动并入 entity source refs；
- claim_id 或 Evidence ID 不存在时 fail closed；
- 日期只对 ISO 格式做确定性归一化，相对日期保留原文。

BC-015 后在投影前增加 `EntityCandidateSet`：

- Action 候选：action_item Claim，或包含明确责任义务的 blocker Claim；
- Risk 候选：risk/blocker Claim；
- 每个 Action 候选必须出现在 action_items，Schema 不提供 Action 排除字段；
- 每个 Risk 候选必须出现在 risks 或 risk_duplicates；
- risk duplicate 必须指向已 selected 的 canonical Risk，并通过文本重合门禁；
- 模型不能新增候选外实体；
- 无支持字段确定性降级，未知 Evidence ID 仍直接失败。

## 运行与可观测

实体投影复用 Analysis/Revision 路由。初次生成和业务修订分别使用对应 EntityBuilder，物理调用进入现有 Model Trace。`claims_built` 事件增加：

- `action_item_count`；
- `risk_count`；
- `entity_projection_model_call_count`。
- `entity_field_downgrade_count` 与 `entity_field_canonicalization_count`；
- 候选数量、selected Claim IDs 和 risk duplicate 决策摘要；
- `dedicated_action_recovery_count`。

StubProvider 不增加模型调用，以保持离线测试确定性。真实回归失败后，Runtime、Run CLI 和 Eval CLI 默认关闭独立投影，只能用 `--entity-projection` 显式实验。

## 风险与后续

- 真实 Provider 每轮增加一次调用，需要用 Token、延迟和字段指标判断收益；
- 当前验证失败仍重建全部 Claim 和实体，尚未实现局部实体修订；
- EntityBuilder 仍是模型判断，业务同一性和去重规则需要更多 Golden Case；
- 第二次真实回归生成 8 个 Action 和 1 个 Risk，Action Precision 50%、Risk Recall 50%、字段支持率 52.38%，最终失败；
- 过投影与发布门禁问题登记为 BC-015；
- 两次候选门禁 Run 已达到字段支持 100%，其中一次 Action/Risk Recall 100%，但分别暴露 Claim 分类波动和专用 Action Evidence 合并；
- 字段原文支持仍可能出现业务角色错误，mitigation false positive 登记 BC-017；
- BC-016/BC-017 回归通过前，本设计不能默认启用。

## 验证

- 新增跨 Evidence 字段合并测试；
- 新增未知 Claim 引用拒绝测试；
- 新增 Stub 兼容测试；
- 全量自动化测试：191 passed。
