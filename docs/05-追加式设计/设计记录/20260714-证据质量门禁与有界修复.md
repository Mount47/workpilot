# 追加项目点设计记录：证据质量门禁与有界修复

## 元信息

- 状态：已实现
- 作者：WorkPilot
- 创建日期：2026-07-14
- 最后更新：2026-07-14
- 关联模块：Evidence、Runtime、Verification、Trace
- 关联问题：首次 qwen-plus Run 中候选大量丢弃、来源遗漏但最终 passed

## 问题与动机

原系统验证“最终写出的结论是否有合法引用”，但没有验证“应该处理的来源是否成功处理”和“已接受证据是否进入最终结论”。真实模型运行证明，仅依靠 Claim/Citation Precision 会掩盖 Recall 和 Coverage 缺陷。

## 用户场景

用户要求综合项目文档和会议纪要生成报告。会议纪要候选因 quote 或行号错误全部被丢弃时，系统应主动修复；会议纪要已有正式 Evidence 但最终报告遗漏它时，系统应要求修订，而不是 passed。

## 产品边界判断

保持受控 Agent 边界：系统规则决定是否修复和最多修复一次，模型只负责重新抽取或修订 Claim，不允许自行无限增加步骤。

## 当前实现

改造前，EvidenceExtractor 会丢弃非法候选，Runtime 只记录总 Evidence 数和总丢弃数，Claim/Citation Verifier 不检查来源覆盖。

## 目标与非目标

### 目标

- 建立每来源、无正文的提取统计；
- 在 Claims 生成前 fail closed；
- 只修复问题来源并限制调用次数；
- 检查 Evidence 到 Claim 的来源覆盖；
- 全过程进入安全 Trace。

### 非目标

- 本阶段不做开放式动态 Planner；
- 不判断来源业务重要性；
- 不实现语义级 Evidence Recall；
- 不自动切换 Parser 或 Provider。

## 备选方案

只记录指标不阻断，无法改变错误报告的状态；任何来源零 Evidence 都失败，则无关历史文件也会阻断。保持现状会继续得到高 Precision、低 Coverage 的报告。

## 最终决策及原因

采用分级策略：显式读取/Provider 错误和“候选全部丢弃”阻断；正常零候选只 warning；全局零 Evidence 阻断；正式 Evidence 来源未进入 Claim 时触发业务修订。

## 模块与依赖影响

- EvidenceExtractor 输出 SourceExtractionReport；
- EvidenceQualityPolicy 不依赖 Provider；
- Runtime 管理两次提取尝试；
- SourceCoverageVerifier 复用 EvidenceStore；
- 原 DAG 和六个 PlanStep 不变。

## 数据和接口变更

新增 `SourceExtractionReport`、`EvidenceQualityCheck`、`EvidenceQualityReport` 和 `EvidenceQualityError`。EvidenceExtractor 新增 `starting_index` 和 `get_source_reports()`。

## 安全、权限和隐私

质量报告不保存 quote 或正文。Runtime Trace 记录计数、规则 ID 和问题来源数量，不记录 Repair Prompt 全文。

## 失败、重试与恢复

Evidence 最多提取两轮；第二轮只处理问题来源。仍失败则 `evidence_quality_failed`。Claim 来源遗漏沿用最多三次 synthesis attempt 的业务修订。

## 可观测性

新增 `evidence_quality_evaluated` 和 `evidence_repair_requested`，可以区分提取质量失败和最终 Claim 验证失败。

## 实施阶段

每来源报告、确定性策略、Runtime 修复、来源覆盖验证、自动化测试和文档同步均已完成。

## 测试与评测

当前覆盖规则判断、ID 连续性、覆盖验证和一次修复成功。后续需要在真实模型 Golden Dataset 中比较 Source Coverage、Evidence Acceptance 和额外成本。

## 验收标准

- 首轮候选全部无效时不进入 Claims；
- 第二轮恢复后正常继续；
- 第二轮仍失败时 Run failed；
- 有 Evidence 的来源被 Claims 遗漏时触发修订；
- Trace 不包含原始正文。

## 实际实施结果

功能已接入现有受控 Agent Loop，140 个测试全部通过。

## 遗留问题与后续项目点

- 将 Gate 纳入 Eval Runner；
- 支持错误到工具替换的受限重规划；
- 实现 attempt 级持久化和恢复。
