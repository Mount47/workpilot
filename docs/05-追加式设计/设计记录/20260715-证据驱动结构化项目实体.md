# 证据驱动结构化项目实体

## 元信息

- 日期：2026-07-15
- 状态：已实现第一阶段
- 关联问题：BC-005
- 影响模块：Domain、ClaimBuilder、Verifier、Synthesizer、Evaluation

## 背景

真实 qwen-plus 回归证明 Claim 与引用可以通过验证，但风险和行动项业务字段长期为空。根因不是单个 Prompt，而是系统缺少能够表达字段来源的正式业务实体。

## 决策

1. Claim 继续承担最小结论与父级 Evidence 边界；
2. ActionItem/Risk 成为 ProjectSnapshot 内的正式实体；
3. 模型在同一次 Claim 构建调用中返回嵌套 Draft，避免新增一次模型调用；
4. 模型侧字段使用扁平 value/refs，Mapper 再生成领域层 SupportedText；
5. Artifact 只渲染正式实体，不做中文正则抽取；
6. 字段支持由独立确定性 Verifier 检查并进入现有修订循环；
7. 相对日期保存原文，不在缺少基准时间和时区语义时强制标准化。

## 为什么不让 Renderer 提取字段

Renderer 无法可靠处理多人、别名、相对日期、跨文档冲突和隐含责任人。把抽取放入展示层还会绕过结构化重试、Evidence 验证和评测，因此 Renderer 必须保持确定性。

## 当前范围与验收

第一阶段完成 ActionItem、Risk、字段验证、Artifact 0.3 与基础评测指标。Milestone 仅建立模型入口，冲突处理、相对日期解析、Golden 字段准确率和局部修订留到后续增量。

- 157 项自动化测试通过；
- 虚构字段和父级之外引用会 fail closed；
- 缺失字段显式输出 null/unknown，不触发虚构；
- 字段支持率和填充率进入 Eval JSON 与 CLI；
