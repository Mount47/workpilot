# 结构化实体 Golden 评测

## 元信息

- 日期：2026-07-15
- 状态：已实现第一版
- 关联问题：BC-005、BC-010
- 影响模块：Evaluation、CLI、StubProvider、Golden Dataset

## 背景

字段 Population Rate 只能回答模型有没有填值，不能回答值是否正确，也不能判断资料中是否本来就没有风险等级。BC-005 需要人工 Golden 标签才能形成可比较的准确率基线。

## 决策

1. 使用 Claim 原文作为实体锚点，不使用运行期 Evidence ID；
2. 匹配时只允许忽略一个 Markdown 列表 marker，不做语义相似匹配；
3. 字段未出现在 Golden 对象中表示“不参与评测”；
4. `{"value": null}` 表示人工确认该字段应为空；
5. 字段不一致同时计一个 False Positive 和一个 False Negative；
6. 非穷举实体集只计算 Entity Recall，避免把合理的额外实体误判为 False Positive；
7. 输出 TP/FP/FN 原始计数以及 Precision/Recall，保证指标可审计。

## 当前字段

- ActionItem Detection；
- Risk Detection；
- Action Owner；
- Action Due Date；
- Risk Owner；
- Risk Severity；
- Risk Mitigation。

## 数据质量约束

- 同类实体的 claim_text 锚点必须唯一；
- 非空标签不能是空白字符串；
- Risk Severity 只允许 low、medium、high、critical 或显式 null；
- Golden 文件不能保存模型生成的 ID 或运行目录路径。

## 第一版基线

`evals/BC-005结构化字段回归.json` 标注 basic_project 的 3 个行动项和 2 个风险。Stub 离线运行结果：

- Action/Risk Entity Recall：100% / 100%；
- 所有结构化业务字段 Recall：0%；
- Evidence、Claim 和 Citation 基线仍为 100%。

该结果符合 Stub 只做确定性证据分类、不做模型字段解析的边界，同时证明评测可以将任务完成率与字段质量分开。

## 后续

第一版只有一个 workspace，不能代表真实业务质量。后续要扩展冲突字段、缺失负责人、跨文档截止日期、相对日期、多负责人和错误风险等级案例，并由真实模型形成版本化对比。
