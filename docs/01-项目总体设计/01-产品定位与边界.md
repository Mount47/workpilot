# 产品定位与边界

## 一句话定位

WorkPilot 是一个面向企业项目协作场景的证据驱动型 Agent。系统从项目文档、会议纪要和任务数据中提取可验证事实，形成项目进展、风险、里程碑、决策和行动项，并生成可追溯的管理报告。

## 核心业务问题

企业项目资料通常分散在文档、会议记录、表格和任务系统中。项目负责人需要反复汇总信息，还会遇到以下问题：

- 同一事项在不同来源中的描述不一致；
- 报告结论无法快速追溯到原始材料；
- 行动项缺少负责人或截止日期；
- 风险和里程碑状态无法跨周期持续跟踪；
- 通用大模型容易补全资料中不存在的事实；
- Agent 的执行过程、消耗和失败原因不可见。

WorkPilot 的核心价值不是“生成一篇流畅的周报”，而是建立从来源、证据、结论到交付物的可信链路。

## 目标用户

- 项目经理与项目办公室；
- 业务项目负责人；
- 交付、实施和咨询团队；
- 需要周期性项目汇报的跨职能团队。

## 核心场景

首个完整场景固定为：

> 综合项目计划、周会纪要、任务清单、风险登记和客户反馈，生成本周期项目报告，识别延期、阻塞、信息冲突及责任人缺失的行动项，并让所有事实性结论可回溯到来源。

## 产品目标

1. **可执行**：能够按照受控计划调用数据源、分析和验证工具；
2. **可验证**：事实性结论必须关联有效证据，证据不足时输出 unknown；
3. **可评测**：抽取、引用、结论支持和任务完成质量都有可重复指标；
4. **可观测**：计划、步骤、工具、模型、成本、延迟和错误形成完整 Trace；
5. **可持续**：通过项目长期记忆支持跨周期状态更新和历史回溯；
6. **可恢复**：失败后能够安全重试、恢复或终止，不产生重复和污染状态。

## 产品边界

WorkPilot 当前聚焦企业项目管理分析，不把以下领域作为主线：

- 企业经营分析：收入、利润、客户、转化率等经营指标不是当前核心模型；
- 研发效能分析：Git、PR、CI 仅作为未来垂直连接器；
- 通用办公助手：不承担无边界的邮件、日历和个人助理任务；
- 高风险事务代理：不自动审批、付款、签约或向外部系统写入关键状态；
- 开放式代码执行：不允许模型任意生成并执行 Shell 或 Python；
- 无边界自主循环：Runtime 必须控制工具、步骤、时间和 Token 预算。

## 核心设计原则

1. **证据优先**：生成质量服从证据质量；
2. **后端掌控控制流**：模型提出计划和内容，Runtime 掌握执行权；
3. **确定性保护优先**：路径、权限、预算、格式和引用检查尽量使用确定性代码；
4. **失败关闭**：无法确认安全性或可信度时，宁可失败或输出 unknown；
5. **记忆不是事实来源**：长期记忆必须保留来源、时间、项目和版本信息；
6. **用评测决定演进**：连接器、检索和规划优化必须用指标证明收益；
7. **渐进式实现**：先形成可测试闭环，再扩展数据源、自治能力和高可用。

## 成熟度目标

WorkPilot 将依次演进为：

```text
可追溯报告生成器
→ 可评测的项目分析 Agent
→ 具备动态规划和记忆的项目管理 Agent
→ 具备真实连接器、恢复能力和可观测性的高可用系统
```
