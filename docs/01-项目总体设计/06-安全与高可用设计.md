# 安全与高可用设计

## 安全目标

- Agent 只能访问 Mission Contract 授权的数据和工具；
- 不同项目的数据、证据、记忆和运行记录互相隔离；
- 敏感内容不会默认完整进入日志或模型请求；
- 外部来源和模型输出均视为不可信输入；
- 失败和超时不会产生无法解释的部分写入。

## 当前已有保护

- Workspace 路径限制；
- 明确的 Mission Contract 模型；
- 有界修订次数；
- 步骤、时间和 Token 预算硬限制；
- 步骤与模型调用级 Trace；
- 引用不存在或原文不匹配时失败关闭；
- 无网络 Stub Provider 支持测试。

## 待实现安全能力

- 工具调用前强制检查白名单；
- 项目和用户权限上下文；
- Prompt Injection 输入隔离；
- 日志脱敏、截断和 Hash；
- 外部连接器最小权限凭证；
- 数据保留、纠错和删除策略；
- Artifact 发布前的敏感信息检查。

## 高可用目标

高可用不等于立即引入分布式架构。首先需要保证：

- 状态可持久化；
- 步骤可重试且幂等；
- 运行可从安全检查点恢复；
- Provider 和连接器失败有明确超时、退避和降级；
- 同一任务不会被重复执行；
- 指标、日志和 Trace 能定位失败；
- 数据库写入具备事务边界。

## 分阶段路径

```text
单进程确定性状态机
→ 持久化 Run 与步骤状态
→ 幂等工具调用和检查点恢复
→ 后台任务队列与并发限制
→ 数据库锁、租约和失败接管
→ 多实例部署与服务级指标
```

当前阶段不优先引入 Kubernetes、复杂微服务和完整企业 IAM。先证明单实例运行的正确性、可恢复性和可观测性，再决定部署复杂度。
