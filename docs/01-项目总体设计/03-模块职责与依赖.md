# 模块职责与依赖

## 模块划分原则

- 单个模块只拥有一类核心职责；
- Runtime 依赖接口，不依赖具体 Provider 或连接器；
- 连接器只负责读取和标准化数据；
- 分析模块只依赖标准化来源、Evidence 和 Memory；
- 生成结果必须经过独立验证模块；
- Trace 通过事件接口接收数据，不反向控制业务流程。

## 核心模块

| 模块 | 主要职责 | 不负责 |
|---|---|---|
| Mission Contract | 定义目标、权限、工具和资源预算 | 生成计划或执行工具 |
| Agent Runtime | 状态迁移、调度、预算、失败与恢复 | 直接实现各类数据解析 |
| Planner | 将目标转换成结构化、可校验计划 | 绕过 Runtime 执行动作 |
| Plan Executor | 解析依赖并执行获准步骤 | 自行扩展工具权限 |
| Tool Registry | 注册工具、校验参数和统一调用协议 | 决定业务分析结论 |
| Connector | 读取数据并输出统一 SourceDocument | 生成报告或修改长期记忆 |
| Evidence Extractor | 从来源中抽取原文证据 | 判断最终结论是否成立 |
| Evidence Store | 保存、索引和校验证据 | 替代长期项目数据库 |
| Project Analyzer | 形成项目状态、冲突和衍生指标 | 访问未授权数据源 |
| Memory Manager | 管理工作、项目和经验记忆 | 把未经验证输出写成事实 |
| Synthesizer | 基于证据和结构化状态生成交付物 | 控制执行流程和安全策略 |
| Verifier | 验证引用、支持度、结构和任务要求 | 自行修改原始来源 |
| Revision Controller | 将验证错误映射为受控修订动作 | 开放式重复生成 |
| Trace & Metrics | 记录事件、耗时、Token、成本与错误 | 存储敏感全文作为默认行为 |
| Artifact Store | 保存和索引交付物 | 承担业务数据库职责 |
| Evaluation | 运行 Golden Cases 并计算指标 | 替代线上监控 |

## 依赖方向

允许的主要依赖方向：

```text
CLI/API → Runtime
Runtime → Contract / Planner / Executor / Verifier / Artifact
Executor → Tool Registry
Connector → Source Model
Extractor → Source Model / Evidence Store / Provider
Analyzer → Evidence Store / Project Model / Memory Interface
Synthesizer → Project Model / Evidence Store / Provider
Verifier → Claim / Evidence / Artifact
Memory Manager → Repository Interface / Policy
Evaluation → Runtime Public Interface
```

禁止形成以下依赖：

- Provider 直接控制 Runtime 状态；
- Connector 直接写最终 Artifact；
- Synthesizer 绕过 Evidence Store 读取原始文件；
- Verifier 依赖 Synthesizer 内部 Prompt；
- 业务模块直接依赖具体数据库驱动；
- Memory 直接把旧报告当成当前事实。

## 模块变更规则

新增模块或改变跨模块接口前，必须完成追加式设计记录。涉及公共数据模型时，还必须更新数据与领域模型、实现细节和迁移策略。
