# WorkPilot 校招项目收尾设计

## 状态

Accepted on 2026-07-23。收尾阶段冻结新的运行时基础设施功能，不进入 HA-02D、可靠队列、多租户或新连接器开发。

## 目标定位

WorkPilot 对外定位为“证据驱动、可验证、具备可靠执行基础的项目分析 Agent”，不宣称已经达到完整企业级高可用。首页和面试叙事必须优先解释业务问题与可信度内核，其次才展示持久化、Checkpoint、幂等和 fencing 等工程深度。

目标读者应在三个时间尺度内理解项目：

- 30 秒：知道它不是普通文本生成 Demo；
- 3 分钟：理解 Evidence → Claim → Verifier → Repair 主链路；
- 15 分钟：能够沿 Checkpoint、Repository 和 Run lease 深挖工程实现。

## 收尾范围

1. 重构根 README，形成定位、差异化、架构、快速演示、工程亮点、能力边界和文档入口的单页叙事。
2. 新增跨平台 Python 演示脚本，只使用 Stub 与脱敏 Fixture，不需要 API Key；运行后验证关键 Artifact 并输出可展示摘要。
3. 新增校招项目介绍与演示验收文档，包含 30 秒介绍、3 分钟讲法、简历要点、常见追问和明确边界。
4. 将路线图状态切换为“功能冻结/展示收尾”，HA-02D 保留为未来演进，不作为本轮交付门槛。
5. 保留完整测试、Python 编译、前端生产构建和补丁检查作为最终门禁。

## 非目标

- 不新增恢复 API、任务队列、鉴权、多租户、容器编排或企业连接器；
- 不重写 Runtime、Evidence、Verifier 或前端交互；
- 不为了演示伪造生产能力、性能数字或真实模型质量；
- 不删除已有深度设计文档，只通过主 README 降低阅读成本。

## Git 交付

先将已验收的 HA-01～HA-02C 工作固化为一个功能基线提交；随后将演示脚本、README 和求职材料作为独立收尾提交。这样面试时既能展示工程演进，也能避免一个无法审阅的混合提交。
