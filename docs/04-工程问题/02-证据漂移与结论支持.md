# 证据漂移与结论支持

## 问题零：Evidence Precision 通过但 Recall 不足

首次 qwen-plus 真实运行扫描两个来源，13 个 Candidate 只接受 3 个，最终只有一个来源进入 ProjectSnapshot。现有 Verifier 能证明保留引用真实，但不能证明重要来源和事实没有遗漏。

处理方向：

- 增加 candidate acceptance rate；
- 增加 source coverage rate；
- 按来源记录丢弃原因；
- 重要来源零 Evidence 时触发定向修复；
- 最终状态区分 validity_passed 与 coverage_passed；
- 使用 Golden Dataset 评测 Evidence Recall，而不是只看最终 Citation Validity。

## 问题一：来源变化

Evidence 抽取后，来源可能被修改。quote 仍可能存在但行号改变，也可能完全消失。仅保存文件名和行号不足以判断 Evidence 是否仍有效。

处理方向：

- 保存来源版本或内容 Hash；
- 保存 ContentUnit Hash；
- 验证时区分 quote 消失和 Locator 漂移；
- 可安全重定位时生成新版本 Evidence；
- 不可确认时将对应 Claim 标记为失效。

## 问题二：引用真实但不支持结论

当前 Citation Verifier 可以证明 Evidence 存在，却不能证明它支持报告中的 Claim。例如引用内容只说“讨论延期”，结论却写成“确定延期两周”。

处理方向：

- 把报告拆成最小 Claim；
- 区分 explicit、derived、analytical 和 unknown；
- 对 explicit/derived 使用确定性规则优先验证；
- 必要时使用 LLM Judge 辅助 Support 判断；
- LLM Judge 不能覆盖引用真实性检查。

## 问题三：多来源冲突

新旧文档、会议纪要和任务表可能对日期、负责人或状态给出不同信息。系统不能静默选择其中一个。

处理方向：

- 保存来源时间、权威级别和版本；
- 建立 Conflict 对象；
- 可以按明确规则自动消解的冲突必须记录规则；
- 无法消解时在报告中展示冲突并请求确认。
