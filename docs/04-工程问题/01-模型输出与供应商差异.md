# 模型输出与供应商差异

## 主要问题

- 模型返回 Markdown Fence 或额外解释；
- JSON 字段缺失、类型错误或枚举越界；
- “没有证据”和“请求失败”都被表示为空数组；
- 不同 Provider 的 Token、停止原因、错误和结构化能力不同；
- 重试可能产生额外成本或重复结果；
- 模型升级后相同 Prompt 的行为发生变化。

## 当前措施

- Structured Output 使用 Pydantic 校验；
- 去除常见 Markdown Fence；
- 设置 temperature=0；
- 允许有限次数重试；
- StubProvider 提供确定性离线测试。

## 后续设计要求

- Provider 返回统一 `GenerationResult`；
- 统一错误类型：超时、限流、认证、格式、内容安全、服务端错误；
- 区分成功空结果与调用失败；
- 保存 Provider、模型和 Prompt 版本；
- 定义幂等与重试边界；
- 对关键结构使用 Schema 校验并显式失败；
- 用评测而不是单次示例判断模型效果。

## 当前进展

已完成数据驱动 Descriptor、能力声明、Gemini/Custom 注册，以及 authentication、rate_limit、timeout、network、server、invalid_response、unknown 分类。统一退避、熔断、原生 Structured Output 选择和真实 Provider 对比评测仍未完成。

## 验证

至少覆盖合法结构、Fence、缺字段、错误类型、空响应、超时、限流、重试成功和重试耗尽。
