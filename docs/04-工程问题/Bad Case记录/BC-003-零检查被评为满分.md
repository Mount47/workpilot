# BC-003：零验证检查被评测为 100%

## 元信息

- 状态：已修复
- 首次发现：2026-07-14
- 最后更新：2026-07-14
- 主要分类：EVALUATION_REGRESSION
- 关联模块：EvalRunner、EvaluationReport、CLI
- 发现 Run：`runs/qwen-plus-bc001-regression`

## 预期结果

Runtime 在 Evidence 阶段失败、没有执行 Claim/Citation 验证时，对应指标应为 N/A，而不是 0% 或 100%。

## 实际结果

首次生成的真实回归 Eval Report 中：

- `actual_status = failed`；
- 没有 `verification_report.json`；
- Citation Check 数为 0；
- Claim Support Check 数为 0；
- Source-to-Claim Check 数为 0；
- 但三个 Rate 因 `empty_value=1.0` 被输出为 100%。

## 影响范围与严重级别

- 严重级别：高；
- 会让失败 Case 在部分质量指标上看起来满分；
- Suite 宏平均可能被无适用样本抬高；
- 会误导项目优化和面试数据表述。

## 根本原因

EvalRunner 没有区分：

```text
0 次检查，因此指标不适用
0 次失败，因此错误率为 0
所有已执行检查通过，因此通过率为 100%
```

旧实现将第一个状态错误地折叠为第三个状态。

## 最终修复

- Citation Validity、Claim Support、Unsupported Claim 和 Claim Source Coverage 改为可空指标；
- 分母为零时返回 `None`；
- Suite 聚合只计算非空 Case；
- 所有 Case 均不适用时 Summary 保持 `null`；
- CLI 将空指标显示为 `N/A`；
- Evidence Precision/Recall 等有明确空集语义的指标保持原规则。

## 回归测试

- Evaluation Error Case 的验证类指标必须为 None；
- `_optional_ratio(0, 0)` 返回 None；
- 宏平均忽略 None；
- 全部 None 时结果仍为 None。

## 遗留问题

已有 `runs/qwen-plus-bc001-regression/eval_report.json` 是发现问题时的原始错误产物，保留用于复盘，不手工篡改。后续新评测将使用修复后的指标语义。

## 面试复盘要点

真实失败 Run 反而暴露了评测系统自己的空集语义错误。零检查不是满分，我将验证类 Rate 改成 Optional，并让宏平均忽略 N/A，避免失败样本虚高整体指标。这说明评测代码本身也必须作为生产逻辑测试，而不能默认可信。
