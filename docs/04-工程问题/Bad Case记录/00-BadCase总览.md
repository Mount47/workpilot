# Bad Case 总览

## 目的

本目录只记录 WorkPilot 开发、测试和真实模型运行中已经发生的异常案例，用于：

- 防止同类问题回归；
- 将真实失败转化为评测样本；
- 保存从现象、根因到修复验证的完整链路；
- 为面试复盘提供可验证的工程案例。

假设风险、尚未发生的问题继续记录在上一级工程问题文档，不登记为 Bad Case。

## 状态定义

| 状态 | 含义 |
|---|---|
| 待分析 | 已确认异常，尚未定位根因 |
| 已定位 | 已找到主要根因，尚未实施修复 |
| 修复中 | 正在修改，或代码已完成但真实场景尚未回归 |
| 已修复 | 修复完成且自动化测试通过 |
| 已回归验证 | 原场景已重新执行并证明问题不再发生 |
| 接受风险 | 明确不修复，并记录原因和边界 |

## 维护要求

- 新案例必须使用唯一的 `BC-XXX` ID；
- Run passed 但业务结果不完整，同样属于 Bad Case；
- 每个案例必须给出 Trace、Artifact、测试或可复现步骤中的至少一种依据；
- 修复后必须关联代码、测试和 Git Commit；
- 没有复跑原始场景，不得标记为“已回归验证”；
- 不记录 API Key、完整敏感 Prompt 或企业原始正文；
- 新增或关闭案例时，同步本总览、项目状态和变更记录。
