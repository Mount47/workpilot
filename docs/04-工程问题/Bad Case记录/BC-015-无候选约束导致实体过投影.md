# BC-015：无候选约束导致实体过投影

## 元信息

- 状态：修复中
- 首次发现：2026-07-15
- 主要分类：MODEL_OUTPUT
- 次要分类：VERIFICATION_CONTRACT、SAFE_ROLLOUT
- 关联模块：EntityBuilder、EntityFieldVerifier、Runtime、Eval CLI
- 发现 Run：`qwen-plus-bc014-entity-builder-regression`

## 预期结果

独立 EntityBuilder 应在保持字段证据正确的前提下，提高跨 Evidence Action/Risk 的召回，并且不能把普通进展、待分配 Issue 或响应记录过度投影成行动项和风险。

## 实际结果

真实 qwen-plus 实验 Run failed：

- Action Item Precision/Recall：50% / 100%，生成 8 条行动项，其中 4 条为误报；
- Risk Precision/Recall：100% / 50%，漏掉支付阻塞风险；
- Action Due Date Precision/Recall：33.33% / 33.33%；
- Risk Mitigation Precision/Recall：100% / 100%；
- Entity Field Support：52.38%；
- 14 个 Entity Verifier error；
- 30861 Token，Runtime 记录 169.24 秒，1 次业务修订后仍失败；
- 修订阶段又因 Action status 枚举输出非法而耗尽结构化重试。

## 根本原因

1. EntityBuilder 面向全部 Claim 做开放式实体发现，没有先生成受控候选集合；
2. 模型把 pending Issue、普通进展和相关响应都解释成 Action；
3. 模型从 `P2` 等业务优先级推断 severity，并从语义推断 status，而不是要求 Evidence 中出现规范枚举文本；
4. 第一版 EntityFieldVerifier 要求 entity source refs 与 Claim refs 完全相等，与跨 Evidence 字段需要 refs 超集的设计冲突；
5. 实验功能未经真实 Golden 通过就成为默认路径，缺少安全发布门禁。

## 已完成收口

- EntityBuilder 改为实验开关，CLI 仅通过 `--entity-projection` 显式启用；
- Runtime/Eval 默认关闭，继续使用已验证的 ClaimBuilder 实体路径；
- Entity Claim 契约改为：source refs 必须精确等于 Claim refs 与字段 refs 的并集；
- 新增跨 Evidence 字段作为受控 refs 超集的验证测试；
- 自动化回归：180 passed。

## 第二阶段修复

已完成：

1. Action Candidate 仅来自显式 action_item，以及包含“需要/必须/负责”等明确义务表达的 blocker；
2. Risk Candidate 来自 risk/blocker Claim；
3. Action 候选必须全部进入 action_items，Schema 不提供排除字段；
4. Risk 候选必须进入 risks 或 risk_duplicates，防止静默漏召回；
5. risk duplicate 必须引用已 selected 的 canonical Claim，并通过文本重合门禁；
6. 未知 Evidence ID 先 fail closed，不能通过字段降级隐藏；
7. 无原文支持的文本字段和枚举字段确定性降级为 unknown，并计入 Trace；
8. ActionStatus 补充 Evidence 中真实存在的 pending；
9. 枚举验证统一空格、连字符和下划线后再匹配。

在 BC005/BC014 已保存真实快照上，系统确定性生成 4 个 Action Candidate 和 3 个 Risk Candidate，符合 Golden 的行动项边界；支付相关两个 Risk Candidate 仍需模型显式去重。当前自动化回归：191 passed。

## 回归状态

候选门禁共完成两次 qwen-plus 回归：

1. lossless candidate Run：Action/Risk Recall 100%，字段支持 100%，但两个 pending Issue 因 Claim 分类波动进入 Action Candidate，Action Precision 仅 66.67%；12915 Token、75.92 秒、无业务修订；
2. canonical candidate Run：文本行动信号排除了 pending Issue，Risk Precision/Recall 100%，但 ClaimBuilder 合并了一条专用 Action Evidence，Action Recall 降为 75%；14636 Token、84.41 秒、无业务修订。

当前候选边界已不再只信任 Claim category，而是要求 Action 文本包含责任、义务或执行信号；保存的两次真实 Snapshot 均可重新得到 4 个 Action、3 个 Risk 候选。剩余问题拆分为 BC-016 和 BC-017。实验开关继续默认关闭，下一次真实 Golden 达标前不启用主路径。

## 面试复盘要点

模块拆分本身不等于效果提升。拆分后的模型边界如果仍然开放，会把“漏抽取”变成“过抽取”。企业级 Agent 的新策略需要 feature flag、离线 Golden 和默认关闭的安全发布流程。
