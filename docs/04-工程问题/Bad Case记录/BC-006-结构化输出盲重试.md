# BC-006：结构化输出盲重试

## 元信息

- 状态：修复中
- 首次发现：2026-07-15
- 主要分类：AGENT_LOOP
- 次要分类：MODEL_OUTPUT、PERFORMANCE_COST
- 关联模块：OpenAIProvider、ClaudeProvider、ClaimBuilder
- 发现 Run：`qwen-plus-bc005-regression`

## 预期结果

模型输出未通过 JSON/Pydantic 校验时，有限重试应明确告知失败字段和错误类型，使第二次调用成为定向 Structured Repair。

## 实际结果

BC-005 首次真实回归中，Evidence 15/15 接受，但 ClaimDraftCollection 连续两次校验失败。第二次调用仍使用完全相同的消息，没有收到第一次失败原因，最终 Run 在 `synthesize.claims` 失败。

两次 Claim 调用分别消耗 3219 和 3231 Token，合计 6450 Token；步骤耗时约 41.17 秒。整个失败 Run 使用 8385 Token。

## 根本原因

Provider 的循环捕获 JSONDecodeError/ValidationError 后直接进入下一轮，没有改变 messages，也没有保存安全的结构化错误摘要。这是“有限次数”实现了，但“修复动作”没有实现。

## 修复

- 从 ValidationError 仅提取字段路径和错误类型，不复制 input；
- JSON 错误仅返回行列位置；
- OpenAI-compatible 使用 assistant 原响应 + user 校验反馈继续会话；
- Claude 重试 Prompt 携带上次响应与相同脱敏反馈；
- 仍保持最多一次 Structured Retry，不增加调用上限；
- 新增错误 JSON、字段类型错误和重试成功测试。

## 当前状态

第二次 qwen-plus 场景中，首次 Claim 构建经 Structured Repair 后成功，证明反馈方向有效；业务修订时三个 Claim 仍只得到笼统 `value_error` 并失败。现已进一步允许代码内白名单中的静态校验消息进入反馈，例如嵌套 action/risk Draft 缺失原因。该增强仅通过自动化测试，尚未再次真实复跑，因此状态仍为“修复中”。

## 面试复盘要点

重试次数有上限不等于重试有效。不同于网络重试，结构化输出失败是确定性内容错误；如果不改变上下文，第二次调用容易重复失败。正确做法是给出可执行、脱敏、Schema 级反馈，而不是简单扩大重试次数。
