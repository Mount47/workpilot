# BC-017：字段原文支持但业务角色错误

## 元信息

- 状态：修复中，第一版规则已实现
- 首次发现：2026-07-16
- 主要分类：SEMANTIC_FIELD_ROLE
- 次要分类：VERIFICATION_FALSE_PASS
- 关联模块：EntityBuilder、EntityFieldVerifier、Entity Golden Evaluation
- 发现 Run：`qwen-plus-bc015-canonical-candidate-regression`

## 预期结果

Risk mitigation 应描述降低、处理或响应风险的动作。字段值不仅要存在于 Evidence 原文，还必须承担正确业务角色。

## 实际结果

支付阻塞 Evidence 中包含“等待 API 设计确认”。模型把它填入 mitigation：

- 文本确实是 Evidence 子串；
- Evidence ID、parent refs 和 Claim contract 全部合法；
- Entity Field Support 为 100%；
- 但 Golden 判断它是阻塞依赖/原因，不是缓解措施；
- Risk Mitigation Precision 因此只有 50%。

## 根本原因

EntityFieldVerifier 当前证明的是 lexical support，而不是 semantic role support。原文存在只能证明“没有凭空编造”，不能证明值被放进了正确字段。

## 第一版修复

- mitigation 必须包含明确响应动作信号，例如排查、修复、降级、回滚、切换、协调、监控等；
- 只有依赖或等待语义时确定性降级为 null；
- 降级进入 `entity_field_downgrade_count`；
- 未知 Evidence ID 仍先 fail closed，不能被降级逻辑吞掉。

## 当前限制

动词白名单是高精度保守基线，不等于完整语义验证。后续应建立字段角色 Golden Case，并比较规则、分类模型和 LLM Judge 的精度、召回与成本。

## 面试复盘要点

证据验证至少有三层：引用存在、文本支持、业务角色正确。只做前两层仍可能产生“有依据但放错字段”的结论。
