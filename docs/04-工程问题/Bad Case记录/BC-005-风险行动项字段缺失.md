# BC-005：风险和行动项业务字段长期为空

## 元信息

- 状态：修复中
- 首次发现：2026-07-14
- 最后更新：2026-07-15
- 主要分类：ENGINEERING_DEFECT
- 次要分类：MODEL_OUTPUT、Domain Modeling
- 关联模块：Claim、ProjectSnapshot、Synthesizer
- 发现 Run：`qwen-plus-first`、`qwen-plus-bc002-regression`

## 预期结果

会议纪要已经明确负责人、时间、风险和缓解动作时，`action_items.json` 与 `risks.json` 应输出受 Schema 约束的业务字段，并保留 Evidence 引用。

## 实际结果

最新真实回归成功生成 5 个 ActionItem 和 3 个 Risk，但：

- 5 个 ActionItem 的 `owner` 全部为 null；
- 5 个 ActionItem 的 `due_date` 全部为 null；
- Risk 的 `severity` 全部为 unknown；
- Risk 的 `mitigation` 全部为 null；
- status 统一硬编码为 open。

原文实际包含“李四”“王五”“张三”“周三”“本周五”等信息。

## 影响范围与严重级别

- 严重级别：高；
- 报告适合阅读，但结构化数据不能直接进入任务系统或风险台账；
- 无法可靠按负责人、截止日期和风险等级查询；
- 不能支撑跨周期项目记忆和状态更新。

## 根本原因

当前 Claim 只表达 text、category 和 Evidence refs，没有正式 ActionItem、Risk、Milestone 领域对象。Synthesizer 为了不让模型绕过验证，只能填入安全占位值。

## 不采用的方案

不在 Renderer 中用正则从中文文本临时提取负责人和日期。该方案无法处理别名、多负责人、相对日期、缺失年份和冲突来源，会把展示层变成不可验证的业务解析器。

## 已完成的第一阶段修复

1. 建立 ActionItem、Risk 正式模型和 Milestone 预留模型；
2. Model Draft 使用受限字段和字段 Evidence refs；
3. EntityFieldVerifier 检查 owner/due_date/severity/status/mitigation；
4. 相对日期保留原文，只有绝对 ISO 日期做确定性标准化；
5. Artifact 0.3 只负责确定性渲染正式领域对象；
6. Eval 增加字段支持率和字段填充率；
7. 157 项领域功能自动化测试通过。

首次原始 qwen-plus Run 在新 Claim Schema 解析阶段失败，尚未进入字段评测；该阻塞另登记 BC-006，正文日志风险登记 BC-007。当前仍未完成冲突验证、Milestone 主链路和字段 Golden Precision/Recall，因此状态保持“修复中”。

## 回归要求

- 有明确负责人时 owner recall/precision 可评测；
- 无负责人时保持 null，不猜测；
- 日期标准化可回溯原文；
- Risk severity 必须有规则或 Evidence 支撑；
- 不允许 Renderer 引入新事实。

## 面试复盘要点

这不是“再写一个 Prompt”就能可靠解决的问题，而是领域模型缺失。当前占位值虽然功能不完整，但避免了模型任意填充不可验证字段。下一阶段应把 ActionItem/Risk 提升为正式证据驱动实体，再谈数据库、记忆和任务系统同步。
