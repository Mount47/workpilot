# BC-005：风险和行动项业务字段长期为空

## 元信息

- 状态：修复中
- 首次发现：2026-07-14
- 最后更新：2026-07-15
- 主要分类：ENGINEERING_DEFECT
- 次要分类：MODEL_OUTPUT、Domain Modeling
- 关联模块：Claim、ProjectSnapshot、Synthesizer
- 发现 Run：`qwen-plus-first`、`qwen-plus-bc002-regression`

## 预期结果

会议纪要已经明确负责人、时间、风险和缓解动作时，`action_items.json` 与 `risks.json` 应输出受 Schema 约束的业务字段，并保留 Evidence 引用。

## 实际结果

最新真实回归成功生成 5 个 ActionItem 和 3 个 Risk，但：

- 5 个 ActionItem 的 `owner` 全部为 null；
- 5 个 ActionItem 的 `due_date` 全部为 null；
- Risk 的 `severity` 全部为 unknown；
- Risk 的 `mitigation` 全部为 null；
- status 统一硬编码为 open。

原文实际包含“李四”“王五”“张三”“周三”“本周五”等信息。

## 影响范围与严重级别

- 严重级别：高；
- 报告适合阅读，但结构化数据不能直接进入任务系统或风险台账；
- 无法可靠按负责人、截止日期和风险等级查询；
- 不能支撑跨周期项目记忆和状态更新。

## 根本原因

当前 Claim 只表达 text、category 和 Evidence refs，没有正式 ActionItem、Risk、Milestone 领域对象。Synthesizer 为了不让模型绕过验证，只能填入安全占位值。

## 不采用的方案

不在 Renderer 中用正则从中文文本临时提取负责人和日期。该方案无法处理别名、多负责人、相对日期、缺失年份和冲突来源，会把展示层变成不可验证的业务解析器。

## 已完成的第一阶段修复

1. 建立 ActionItem、Risk 正式模型和 Milestone 预留模型；
2. Model Draft 使用受限字段和字段 Evidence refs；
3. EntityFieldVerifier 检查 owner/due_date/severity/status/mitigation；
4. 相对日期保留原文，只有绝对 ISO 日期做确定性标准化；
5. Artifact 0.3 只负责确定性渲染正式领域对象；
6. Eval 增加字段支持率、填充率和 Golden Precision/Recall；
7. 建立 3 个行动项、2 个风险的 BC-005 字段 Golden Case。

第二次 qwen-plus Run 已成功构建第一版实体：Action owner 填充率 100%、due date 33.33%、Risk owner 66.67%、severity/mitigation 0%。Run 后续因 Claim marker 校验和修订 Schema 失败而未通过，分别登记 BC-008 与 BC-006。当前结果证明字段链路开始生效，但不代表字段准确率或 BC-005 已回归完成。

Stub Golden 基线已证明 Action/Risk 实体召回可达到 100%，但 Stub 不解析业务字段，所以字段 Recall 为 0%。下一次 qwen-plus 回归将直接输出字段 Precision/Recall，不再用 Population Rate 代替准确率。

第三次 qwen-plus Golden 回归仍在 Claim 构建阶段失败，脱敏错误证明模型把简单字段输出为字符串/null，而旧 Draft 要求 SupportedText 嵌套对象。该问题登记为 BC-011，现已完成扁平 Draft 改造，但尚未真实复跑。

扁平 Draft 修复后已真实复跑：结构化实体成功生成且字段 Evidence Support 为 100%，证明 BC-011 修复有效；但 explicit Claim 全部发生正文漂移，业务修订又遇到 blocked 枚举缺失，分别登记 BC-012、BC-013。BC-005 仍保持“修复中”。

primary Evidence 与 blocked 修复后的 qwen-plus Run 已 passed：Evidence/Claim/Citation/Entity Field Support 和实体 Recall 均为 100%，owner P/R 为 100%。Due Date Recall 仍为 50%、Mitigation Recall 为 0%，因此 BC-005 核心链路已验证，但完整字段召回尚未达标，剩余问题登记为 BC-014。

## 回归要求

- 有明确负责人时 owner recall/precision 可评测；
- 无负责人时保持 null，不猜测；
- 日期标准化可回溯原文；
- Risk severity 必须有规则或 Evidence 支撑；
- 不允许 Renderer 引入新事实。

## 面试复盘要点

这不是“再写一个 Prompt”就能可靠解决的问题，而是领域模型缺失。当前占位值虽然功能不完整，但避免了模型任意填充不可验证字段。下一阶段应把 ActionItem/Risk 提升为正式证据驱动实体，再谈数据库、记忆和任务系统同步。
