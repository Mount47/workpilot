# 安全与数据隔离

## 输入威胁

项目文档和外部系统内容都是不可信输入，可能包含：

- 诱导模型忽略系统规则的 Prompt Injection；
- 伪造的工具调用指令；
- 敏感信息；
- 恶意路径或文件；
- 超大内容和解析炸弹；
- 误导性来源和过期数据。

## 当前保护

WorkspaceTools 将文件访问限制在 workspace root；Runtime 的修订次数有上限；Citation Verifier 对无效来源执行失败关闭。

## 待实现保护

- 使用 `Path.is_relative_to()` 等可靠方式进行路径边界检查；
- 工具调用必须来自 Tool Registry 并通过 Contract；
- 连接器凭证使用最小权限；
- 来源内容与系统指令严格分隔；
- 文件类型、大小、数量、解析时间和输出大小限制；
- Trace 默认只记录摘要、Hash 和脱敏字段；
- 项目、用户和 Run 三层隔离；
- Artifact 发布前敏感信息检查；
- 对 Memory 读写执行权限和项目过滤。

## 验证要求

安全测试至少覆盖路径穿越、符号链接、恶意文档指令、跨项目 Memory、超大输入、非法 Tool 参数和日志敏感字段。
