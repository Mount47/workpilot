# 证据抽取与存储实现

## 对应代码

- `src/workpilot/evidence/extraction.py`
- `src/workpilot/evidence/quality.py`
- `src/workpilot/evidence/store.py`
- `src/workpilot/providers/base.py`

## 抽取流程

1. Runtime 获取 workspace 文件列表；
2. EvidenceExtractor 逐文件读取内容；
3. Provider 返回 `EvidenceCandidate` 列表；
4. Extractor 验证 quote、行号和行窗口；
5. 合格候选获得本次运行内的 `E-XXXX` ID；
6. Runtime 插入内存 EvidenceStore；
7. EvidenceQualityPolicy 检查来源覆盖与候选接受情况；
8. 失败时只对问题来源执行一次有界修复。

详细门禁、修复策略和 Trace 见《16-证据质量门禁与修复循环》。

## 验证规则

- quote 不能为空；
- quote 必须是来源内容的精确子串；
- `start_line >= 1`；
- `end_line >= start_line`；
- `end_line` 不得超过文件总行数；
- quote 必须存在于声明行号窗口中。

## EvidenceStore

当前以字典保存 Evidence，支持插入、按 ID 查询、列出、计数和导出。相同 ID 会覆盖已有记录。

## 当前限制

- Candidate 与验证后的正式 Evidence 已使用不同模型；
- ID 依赖抽取顺序，只在一次运行内稳定；
- 无去重和来源 Hash；
- Store 不持久化；
- Provider 对每个文件独立调用，未处理上下文过长和并发；
- 丢弃原因已有聚合 Trace，尚未逐条输出以避免敏感内容泄露；
- 只支持文件行号定位。

## 已有测试

覆盖证据存在、ID 唯一、修复 ID 连续、quote 匹配、行号匹配、非法 quote、非法行号、多 Evidence 类型、每来源统计和端到端修复。
