# 追踪日志实现

## 对应代码

- `src/workpilot/trace/journal.py`
- `src/workpilot/runtime/runner.py`

## 当前结构

TraceJournal 是运行内追加式事件列表。每个事件包含：

- event_id；
- sequence；
- run_id；
- step_id；
- parent_step_id；
- event_type；
- data；
- UTC timestamp。

Runtime 当前记录：

- run_started；
- step_started / step_completed / step_failed；
- model_call_completed；
- model_route_selected / model_call_retry_scheduled / model_route_failed_over；
- plan_created / plan_validated；
- plan_step_started / plan_step_completed / plan_step_failed；
- workspace_scanned；
- evidence_extracted；
- artifacts_generated；
- verification_completed；
- revision_requested；
- run_completed 或 run_failed。
- budget_summary。

运行结束后导出为 `trace.json`。

## 当前限制

- Tool Registry 已建立，但还没有统一 Tool Handler/ToolResult 调用协议和 tool_call 事件；
- estimated_cost 暂未计算；
- 模型调用已有 TaskType、Prompt/Schema 版本，Tool 版本尚未实现；
- Provider 错误已经使用稳定枚举，其他运行时错误仍可能使用 Python 类名；
- 默认 data 没有脱敏与大小限制；
- Trace 只写本地文件，无法流式查询和聚合指标。

## 改造方向

下一版应补齐统一 tool_call 事件、字段脱敏、持久化和指标聚合，并继续保持 Trace 与 Working Memory 的步骤状态一致。
