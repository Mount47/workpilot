# 报告生成实现

## 对应代码

- `src/workpilot/synthesis/synthesizer.py`
- `src/workpilot/artifacts/writer.py`

## 当前交付物

- `weekly_report.md`；
- `risks.json`；
- `action_items.json`；
- `project_snapshot.json`；
- `plan.json`；
- Runtime 另外写出 `verification_report.json`、`run_context.json` 和 `trace.json`。

## 当前生成方式

StubProvider 将每条正式 Evidence 确定性转换成 explicit Claim；真实 Provider 通过 ClaimBuilder 生成结构化 Claim Draft。系统统一分配 Claim ID 并构建 ProjectSnapshot。

Synthesizer 不再自由生成新的业务事实，而是按 ClaimCategory 将同一个 Snapshot 确定性渲染为周报、风险、行动项和 Snapshot JSON。缺少某类 Claim 时输出 `No data. [unknown]`。

Evidence 和 Claim 保留 Markdown 原文 marker；Weekly Report 在展示层移除一个前导列表 marker 后再应用统一 bullet，避免 `- - item`。该转换不修改 Snapshot 和 Evidence。Risk/ActionItem 的 title 使用展示文本，description 仍保留原始 Claim。

该设计确保 Markdown 和结构化 JSON 不会产生绕过 Claim 验证的新结论。

## ArtifactWriter

根据内容类型写文本或 JSON，并确保输出目录存在。

## 当前限制

- 风险和行动项尚未使用完整 Pydantic 领域模型；
- owner、due_date、severity 和 mitigation 当前仍是安全占位值，见 BC-005；
- 未生成独立的里程碑、决策和冲突领域对象；
- 反馈修订会重建整个 Snapshot；
- Artifact 写入没有事务、版本和数据库索引；
- Prompt 没有独立版本管理。
