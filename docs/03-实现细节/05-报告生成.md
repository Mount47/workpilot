## 当前生成方式

StubProvider 将每条正式 Evidence 确定性转换成 explicit Claim；真实 Provider 通过 ClaimBuilder 生成结构化 Claim Draft，并在 action/risk Claim 内同时返回字段 Draft。系统统一分配 Claim、ActionItem 和 Risk ID 并构建 ProjectSnapshot。

Synthesizer 不再自由生成新的业务事实，而是按 ClaimCategory 将同一个 Snapshot 确定性渲染为周报、风险、行动项和 Snapshot JSON。缺少某类 Claim 时输出 `No data. [unknown]`。

Evidence 和 Claim 保留 Markdown 原文 marker；Weekly Report 在展示层移除一个前导列表 marker 后再应用统一 bullet，避免 `- - item`。该转换不修改 Snapshot 和 Evidence。Risk/ActionItem 的 title 使用展示文本，description 仍保留原始 Claim。

`action_items.json` 与 `risks.json` 当前 Schema 为 0.3，包含字段值和 `field_evidence`。该设计确保 Markdown 和结构化 JSON 不会产生绕过 Claim 与字段验证的新结论。

## ArtifactWriter

根据内容类型写文本或 JSON，并确保输出目录存在。

## 当前限制

- ActionItem/Risk 已使用正式领域模型，但尚未完成真实模型原场景回归；
- 未生成完整的里程碑、决策和冲突领域对象；
- 反馈修订会重建整个 Snapshot；
- Artifact 写入没有事务、版本和数据库索引；
- Prompt 没有独立版本管理。
