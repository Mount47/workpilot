## Provider 接口

当前 LLMProvider 定义：

- `generate_structured()`；
- `generate_text()`；
- `extract_evidence_from_file()`。

接口已经统一返回可观测结果：

- GenerationResult：一次物理调用的内容、Provider、模型、Token、延迟、请求 ID、停止原因和预估成本；
- StructuredGenerationResult：已校验对象与全部重试调用；
- EvidenceExtractionResult：候选 Evidence、全部调用和显式 error_type。

## 支持情况

- Stub：离线、确定性测试；
- OpenAI-compatible：OpenAI、DeepSeek、Qwen/百炼、GLM、Gemini；
- Claude：使用 Anthropic 原生 SDK；
- Custom：任意显式配置 model、base_url 和 API Key 的企业兼容网关。

## Descriptor 与能力边界

`providers/specs.py` 为每个名称定义：

- ProviderTransport；
- 默认模型和 base_url；
- 文本生成；
- 结构化输出模式；
- Token Usage；
- 原生 Tools；
- 多模态输入。

Capabilities 描述的是 WorkPilot Adapter 当前暴露的能力，而不是底层模型理论上的全部能力。例如 Gemini 模型具备多模态和原生工具，但当前兼容 Adapter 只声明文本与校验式结构化输出。

## Registry

Registry 根据 Descriptor 构建 Adapter：Claude 进入 Anthropic native；其他内置兼容厂商进入 OpenAIProvider；Stub 使用确定性实现。`custom` 没有默认 model/base_url，缺少任一配置都会明确失败。

可以运行：

```bash
workpilot providers
```

查看所有注册名称、transport、默认模型和结构化模式。

Settings 从环境变量和 `.env` 读取配置，Registry 负责默认模型、Base URL 与 API Key 映射。

每个 Provider 只读取自己的 Key 映射。OpenAI-compatible Adapter 不再扫描其他厂商环境变量；缺 Key、Model、Base URL 或 URL 不安全时，Registry 在 SDK Client 创建前抛出 ProviderConfigurationError。

## 离线配置预检

```bash
workpilot doctor --provider deepseek
```

Doctor 检查 Provider、Transport、Model、Base URL、API Key 是否存在、结构化输出能力和本地 Ready 状态。它不创建 SDK Client、不发送请求、不产生 Token，也不保存或显示 Key 值。

检查完整路由：

```bash
workpilot doctor --route-config ./examples/model_routes.json
```

路由预检会逐个检查主备 Target 及其能力要求。Ready 只说明本地配置完整，不代表远端 Key、模型名称和账号权限已经验证。

## 重试与任务路由

RetryPolicy 只处理统一 ProviderCallError 中的限流、超时、网络和服务端瞬时故障。认证失败不会重试；每次物理尝试前都会重新检查 Run 时间与 Token 预算。JSON/Pydantic 解析失败仍属于 Provider 内部的 Response Validation Retry，两类重试分别计数。

ModelRouter 按 TaskType 选择显式 ModelRoute。Route 声明：

- 有序 Provider/模型目标；
- economy、balanced、premium 内部档位；
- 最低允许档位；
- 结构化输出、原生工具和多模态能力要求；
- 是否允许瞬时故障后的备用模型切换。

Runtime 已接入 `planning`、`evidence_extraction`、`analysis` 和 `revision` 路由。`semantic_verification` 已能配置，但对应语义验证能力尚未进入主链路。

路由文件使用 schema version 1.0。示例见 `examples/model_routes.json`，其中禁止保存 API Key。CLI 使用 `--route-config` 启用。

## 版本化调用 Trace

TaskRoutedProvider 为成功物理调用补充 task_type、prompt_version、schema_name、schema_version 和 route_target_index。Trace 同时记录 route selected、retry scheduled 和 failed over 事件，但不记录 Prompt 正文。

## 结构化输出

OpenAI-compatible（包括 Gemini 兼容入口）和 Claude Provider 都支持将 Pydantic Schema 放入系统提示，解析 JSON 并在失败时重试。Evidence 抽取使用 JSON 数组协议，无法解析时返回空列表。

ClaimBuilder 使用 `generate_structured()` 获取 ClaimDraftCollection。ClaimDraft 在 Provider 解析阶段验证 Evidence 引用契约，使缺少引用或衍生过程的模型输出能够在进入正式 Claim 前触发 Provider 有限重试。

## 当前限制

- estimated_cost 尚未接入版本化价格表；
- Provider 错误、RetryPolicy 和显式 Failover 已完成，但尚未实现熔断；
- Evidence JSON 失败已能与“没有证据”区分，但尚未按错误率决定整次 Run 是否失败；
- 已有 Rate Limit 退避和受控故障转移，尚无熔断和跨进程限流；
- Claude、OpenAI-compatible、Gemini Registry 和错误分类已有 Mock 测试；
- 真实模型端到端质量没有评测数据。
- Doctor 已完成离线配置检查，尚无可选的低成本远端认证健康检查。
