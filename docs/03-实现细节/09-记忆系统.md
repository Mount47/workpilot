# Working Memory 实现

## 对应代码

- `src/workpilot/memory/working.py`
- `src/workpilot/runtime/runner.py`

## 职责边界

WorkingMemory 只服务一次 Run，回答“当前状态是什么”。Trace 继续回答“状态如何变化”。它不调用 Provider、连接器或数据库，也不跨项目共享数据。

## 当前状态

WorkingMemory 聚合：

- Mission Contract 安全摘要；
- 当前 Plan 的安全执行状态；
- MemoryStep 生命周期；
- EvidenceStore；
- 当前 ProjectSnapshot；
- 最新验证摘要；
- 当前修订反馈和修订次数；
- 已生成 Artifact 名称；
- Budget Snapshot；
- Run 状态和最后错误类型。

## 步骤生命周期

Runtime 在 `_step()` Context 中调用：

```text
start_step
→ complete_step
或 fail_step
```

重复 step_id、完成后再次完成、未知步骤都会被拒绝。预算在步骤开始、完成、失败和模型调用后同步。

## Evidence 与 Snapshot

WorkingMemory 持有 EvidenceStore，Runtime 通过 `add_evidence()` 注册正式 Evidence。每轮 Claim 构建完成后更新当前 ProjectSnapshot，但安全导出只包含 Evidence ID、Snapshot ID 和 Claim ID。

## 验证与修订

`record_verification()` 只保存检查总数、error/warning 数量以及 check_id、severity、location，不保存可能包含业务正文的 message。修订反馈仅在内存中供下一轮 ClaimBuilder 使用；安全导出只记录是否存在反馈及修订次数。

## run_context.json

成功、普通失败和预算失败都会在 finally 中输出 RunContext。文件包含：

- Run 和 Contract 摘要；
- 步骤状态；
- Evidence 与 Claim ID；
- 验证与修订摘要；
- Artifact 名称；
- 最终预算状态；
- 最后错误类型。

它不包含 Evidence quote、Claim 文本、Prompt、模型响应、修订反馈正文和 Artifact 全文。

Plan 安全摘要只包含 plan_id、created_by、validated、Step ID、Tool、依赖、状态、attempt 和错误类型，不导出可能包含业务数据的 inputs 或 objective。

## 当前限制

- 仅进程内有效；
- 不支持跨进程恢复；
- 没有数据库 Repository；
- 没有项目长期记忆；
- 没有记忆过期、版本、冲突和跨周期差异；
- Artifact 内容仍由 Runtime 局部变量管理。

## 测试

覆盖生命周期约束、安全导出、验证与修订摘要、Run ID 隔离，以及成功、步骤预算失败和 Token 预算失败的 Runtime 集成。
