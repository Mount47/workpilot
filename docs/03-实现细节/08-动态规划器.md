## 当前定位

当前完成的是受控规划基础和 DeterministicPlanner，不是 LLM 动态规划。它的价值是确保计划是实际控制结构，而不是只用于展示的文本。

## 默认计划

```text
scan_workspace
→ extract_evidence
→ build_claims
→ render_artifacts
→ verify
→ finalize
```

每个 PlanStep 包含目标、工具、输入、依赖、期望输出、成功标准、Evidence 要求、状态、attempt 和最后错误类型。

## Tool Registry

当前注册六个高层 ToolSpec：

- workspace.scan；
- evidence.extract；
- claims.build；
- artifacts.render；
- verification.run；
- artifacts.finalize。

ToolSpec 声明是否允许 reentry、是否要求 Evidence。Registry 目前管理规格，实际 Handler 仍由 Runtime 显式提供。

## PlanValidator

执行前确定性检查：

- Step ID 唯一；
- Tool 已注册；
- Tool 存在于 Mission Contract 白名单；
- 所有依赖存在；
- 依赖图无环；
- evidence_required 与 ToolSpec 一致；
- max_steps 能覆盖 planning 和初始计划。

任何错误都会在业务 Tool 执行前 fail closed。

## PlanExecutor

Executor 检查依赖状态并维护 pending、running、completed、failed 与 attempt。只有 ToolSpec 声明 reentrant 的步骤可以被 Runtime 明确重入。

当前 Revision Loop 只重入：

```text
claims.build
artifacts.render
verification.run
```

workspace.scan、evidence.extract 和 artifacts.finalize 不会因生成验证失败而重复执行。

## 状态和交付物

- WorkingMemory 导出 Plan ID、创建方式、校验状态和安全 Step 摘要；
- `plan.json` 保存成功 Run 的完整最终计划状态；
- Trace 记录创建、验证和每个 PlanStep attempt。

## 当前限制

- Planner 仍为确定性固定计划；
- 尚无受限 LLM Planner；
- Handler 参数没有统一 Schema；
- Executor 不进行自动拓扑排序和并行调度；
- success_criteria 尚未被自动判定；
- 尚无步骤跳过、取消、幂等键和持久化恢复。

## 测试

覆盖默认计划、未知工具、循环依赖、预算不足、依赖未完成、reentry 限制、Handler 失败，以及验证失败后只有三个允许步骤发生第二次 attempt。
