# 运行时状态机实现

## 对应代码

- `src/workpilot/runtime/__init__.py`
- `src/workpilot/runtime/runner.py`
- `src/workpilot/contracts/__init__.py`
- `src/workpilot/planning/scheduler.py`
- `src/workpilot/providers/retry.py`

## 当前职责

`Runtime` 创建 Run、MissionContract、WorkingMemory、Tool Registry、Planner、PlanValidator、WorkspaceTools、TraceJournal、Synthesizer 和 ArtifactWriter。EvidenceStore 由 WorkingMemory 持有，Runtime 保留兼容别名。

Planning 步骤先创建并验证 Plan，然后 PlanExecutor 才能触发真实 Handler。当前六个主要业务操作由 SerialDAGScheduler 根据 dependencies 调度，不再由未校验的直接流程调用。

Runtime 同时创建 ExecutionBudget。每个逻辑步骤进入前消耗 step budget；每次物理模型调用返回后累计 input/output Token；步骤开始和完成边界检查 wall-clock 时间。

当前主流程：

```text
pending
→ planning
→ retrieving
→ ClaimBuilder 构建 ProjectSnapshot
→ synthesizing（从 Snapshot 渲染）
→ verifying
→ revising（仅验证失败时）
→ verifying
→ passed / failed
```

## 修订循环

`MAX_SYNTHESIS_ATTEMPTS = 3`。第一次生成失败后，Runtime 把 ClaimSupportVerifier 与 CitationVerifier 的具体错误格式化成反馈，下一轮重新构建 Claims 并渲染 Artifact。三次后仍有 error 则 fail closed。

当前修订已经在 Claim 构建阶段应用反馈，只重入 Claim、Artifact 和 Verify 三个 PlanStep，但仍重建整个 Snapshot，不是单 Claim 级定向修复。完整循环分层见《15-AgentLoop与三类重试》。

## 异常处理

`execute()` 捕获顶层异常，将错误写入 `failure_reason` 和 `run_failed` Trace，最后无论成功失败都写出 `trace.json`。

finally 同时同步最终 Budget Snapshot，并写出安全的 `run_context.json`。它是当前状态摘要，不是可跨进程恢复的完整检查点。

## 当前限制

- `planning` 已调用 DeterministicPlanner 或受限 LLM Planner，但 RuntimePlanPolicy 仍固定六个核心步骤；
- Provider 内部结构化重试会产生独立 GenerationResult，但当前基本使用相同 Prompt；
- 状态迁移只阻止终态后继续迁移，没有校验合法迁移边；
- Run、Contract 和中间状态不持久化；
- 验证 warning 不会导致失败；
- 失败后不能恢复。
