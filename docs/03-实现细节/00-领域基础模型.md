# 领域基础模型实现

## 对应代码

- `src/workpilot/domain/models.py`
- `src/workpilot/domain/__init__.py`

## 当前模型

### SourceLocator

统一描述 Evidence 在来源中的位置。当前正式支持 `file_line`，并预留 PDF 页码、表格范围和外部记录类型。文件行号 Locator 会验证行号范围，并能输出 `meeting.md:L3-L5` 形式的稳定显示值。

### Evidence

表示已经通过来源校验、可以被引用的正式证据。它与 Provider 输出的 `EvidenceCandidate` 分离，包含：

- evidence_id；
- SourceLocator；
- quote；
- evidence_type；
- 可选 source_hash；
- 创建时间和扩展 metadata。

当前 Evidence 提供 `source_file`、`start_line` 和 `end_line` 兼容属性，使现有 Synthesizer 与 Citation Verifier 可以渐进迁移。

### Claim

表示可以独立验证的最小结论，区分：

- explicit_fact；
- derived_fact；
- analytical_judgement；
- unknown。

Claim 同时包含 progress、decision、risk、blocker、action_item、context 和 requirement_change 业务分类，用于确定性生成不同 Artifact。

非 unknown Claim 必须至少包含一个 Evidence 引用；derived_fact 还必须记录 derivation。Claim 尚未接入当前报告生成主链路。

### ActionItem、Risk 与 SupportedText

ActionItem 和 Risk 已成为正式领域实体，通过 claim_id 关联父 Claim。owner、due_date_text 和 mitigation 使用 SupportedText 同时保存字段值和 Evidence refs；已知状态与风险等级也必须保存字段 Evidence。

Milestone 已建立最小版本化形状，但尚未接入抽取和验证主链路。

### ProjectSnapshot

表示一个时间点的项目状态版本，当前包含项目 ID、Snapshot ID、来源 ID、Claims、ActionItems、Risks 和 Milestones。

## 当前接入情况

EvidenceExtractor 已经把 Provider 的 EvidenceCandidate 校验并转换为正式 Evidence；EvidenceStore 只保存正式 Evidence。ClaimBuilder 将 Evidence 转成 Claims 和结构化实体，Synthesizer 再从 Snapshot 确定性渲染全部 Artifact。完整 Milestone、冲突对象和跨周期版本仍未实现，因此领域模型整体仍为 🚧。

## 测试

`tests/test_domain_models.py` 覆盖 Locator、Evidence、Claim、SupportedText 和结构化实体约束；ClaimBuilder、EntityFieldVerifier 和 Synthesizer 另有独立测试。
