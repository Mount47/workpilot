# 引用验证实现

## 对应代码

- `src/workpilot/verification/base.py`
- `src/workpilot/verification/citation_verifier.py`
- `src/workpilot/verification/source_coverage_verifier.py`

## 输入

CitationVerifier 接收：

- 当前 Run 的 EvidenceStore；
- WorkspaceTools；
- 待验证 Artifact 字典。

Markdown 使用 `[E-XXXX]` 格式；结构化 JSON 会递归查找 `source_refs` 列表。

## 检查顺序

1. Evidence ID 是否存在；
2. Evidence 指向的来源文件是否存在且可访问；
3. quote 是否存在于当前来源内容；
4. quote 是否存在于声明行号范围。

检查结果包含 `check_id`、status、severity、Artifact、位置和消息。

## 失败策略

不存在的 Evidence、来源或 quote 产生 error；行号范围不匹配产生 warning。Runtime 只把 failed + error 视为必须修订的问题。

## 当前限制

- 不检测事实性 bullet 完全没有引用；
- 不判断引用是否真正支持对应结论；
- 不验证来源是否在抽取后被修改；
- 正则只接受四位数字 Evidence ID；
- 结构化数据只识别名为 `source_refs` 的字段；
- warning 不阻止最终通过；
- 没有 Schema、Contract 和 Trace 验证器。

## Claim-Support Verifier

`claim_support_verifier.py` 已接入 Runtime：

- 检查所有非 unknown Claim 的 Evidence 引用是否存在；
- explicit_fact 必须与至少一个引用 Evidence 的 quote 完全一致；
- derived_fact 必须在模型层具有 derivation 和输入 Evidence；
- unknown 必须不引用 Evidence；
- analytical_judgement 当前返回 `semantic_support_pending`，不会伪装成已经完成语义验证。

Claim error 与 Citation error 都会进入同一有界修订循环。

## Source-Coverage Verifier

`source_coverage_verifier.py` 检查每个拥有正式 Evidence 的来源是否至少有一条 Evidence 被最终 Claim 引用。遗漏产生 `source.claim_coverage` error，并进入同一个有界业务修订循环。

该规则验证来源覆盖，不等于语义级 Evidence Recall；详细设计见《16-证据质量门禁与修复循环》。

## 已有测试

覆盖有效引用、不存在 ID、quote 不匹配、来源不存在、来源到 Claim 覆盖、行号 warning 和结构化引用。
