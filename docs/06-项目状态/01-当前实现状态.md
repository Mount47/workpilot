## 首次真实模型基线

2026-07-14 已使用百炼 qwen-plus 在脱敏 basic_project 上完成一次 passed Run：4 次物理模型调用、3682 Token、1 次业务修订。系统当时验证了最终 Claim 和 Citation 的有效性，但 13 个 Evidence Candidate 只接受 3 个，且一个已扫描来源未进入最终 Snapshot。该问题现已通过 Evidence Quality Gate、有界 Repair 和 Source-to-Claim Coverage Verifier 建立第一版防线，仍需重新运行真实模型验证收益与成本。

该结果只证明真实 API 链路、结构约束和验证修订闭环可用，不证明信息覆盖率达到企业要求。详细问题见《04-工程问题/08-qwen-plus首次真实运行复盘》。

同日使用相同 Case 完成修复后真实回归：Evidence Repair 被触发 1 次，额外消耗 862 Token，但未恢复有效来源；Runtime 在 Evidence Gate 正确失败，没有继续生成不完整报告。BC-001 的 false-pass 缺陷已验证修复，Repair 无效登记为 BC-002。回归还发现零验证检查被错误计为 100%，已通过 Optional Metric 修复并登记为 BC-003。

2026-07-15 完成 BC-002 第二次 qwen-plus 回归：15 个 Candidate 全部接受，Evidence Precision/Recall、Acceptance、Source Coverage 和 Claim Source Coverage 均为 100%，没有触发模型 Evidence Repair。Run 经 1 次 Claim 业务修订后 passed，总 Token 6581、运行耗时 47.38 秒。Locator Repair Count 为 0，说明本次真实收益主要来自行号视图 Prompt。产物仍暴露 Markdown 双 marker 和结构化业务字段占位，分别登记 BC-004、BC-005；BC-004 已通过确定性展示层修复。

同日完成 BC-005 qwen-plus Golden passed 回归：5 次物理调用、14782 Token、99.23 秒、1 次业务修订恢复，最终 68 项验证零错误。Evidence、Claim、Citation、Entity Field Support 和 Action/Risk Entity Recall 均为 100%；Owner P/R 100%，Due Date P/R 100%/50%，Mitigation Recall 0%。剩余跨 Evidence 字段召回登记为 BC-014。

以上数字只描述当前本地审计结果，后续以自动化报告更新，不能作为长期固定指标。
