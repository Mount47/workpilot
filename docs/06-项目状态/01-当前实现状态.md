# 当前实现状态

## 状态日期

2026-07-23

## 当前定位

当前代码已经形成工程严谨度较高的证据门控项目报告 Agent：从 Evidence、Claim、Verifier、Repair 到 Artifact 建立了“结论可追溯到原文、缺证据 fail closed”的正确性内核，并具备受限 LLM 规划、确定性降级、串行 DAG、三类预算、多 Provider、Trace/Eval、HTTP API 和 React 可追溯前端。HA-01、HA-02A/B/C 已完成 PostgreSQL 执行账本、API 请求幂等、版本化 Checkpoint、内部恢复重建、Run 租约、Heartbeat 和旧 Worker fencing；自动恢复入口、Provider 调用去重、身份隔离、可靠队列和生产运维仍未完成，因此不能宣称为完整高可用企业级系统。

当前进入面向校招的功能冻结与收尾阶段：定位为“证据驱动、可验证、具备可靠执行基础的项目分析 Agent”，即 production-oriented prototype。冻结期间不启动 HA-02D、HA-03、任务队列、连接器或长期 Memory；只接受演示阻断、回归缺陷、安全问题和文档事实错误。

## 首次真实模型基线

2026-07-14 已使用百炼 qwen-plus 在脱敏 basic_project 上完成一次 passed Run：4 次物理模型调用、3682 Token、1 次业务修订。系统当时验证了最终 Claim 和 Citation 的有效性，但 13 个 Evidence Candidate 只接受 3 个，且一个已扫描来源未进入最终 Snapshot。该问题现已通过 Evidence Quality Gate、有界 Repair 和 Source-to-Claim Coverage Verifier 建立第一版防线，仍需重新运行真实模型验证收益与成本。

该结果只证明真实 API 链路、结构约束和验证修订闭环可用，不证明信息覆盖率达到企业要求。详细问题见《04-工程问题/08-qwen-plus首次真实运行复盘》。

同日使用相同 Case 完成修复后真实回归：Evidence Repair 被触发 1 次，额外消耗 862 Token，但未恢复有效来源；Runtime 在 Evidence Gate 正确失败，没有继续生成不完整报告。BC-001 的 false-pass 缺陷已验证修复，Repair 无效登记为 BC-002。回归还发现零验证检查被错误计为 100%，已通过 Optional Metric 修复并登记为 BC-003。

2026-07-15 完成 BC-002 第二次 qwen-plus 回归：15 个 Candidate 全部接受，Evidence Precision/Recall、Acceptance、Source Coverage 和 Claim Source Coverage 均为 100%，没有触发模型 Evidence Repair。Run 经 1 次 Claim 业务修订后 passed，总 Token 6581、运行耗时 47.38 秒。Locator Repair Count 为 0，说明本次真实收益主要来自行号视图 Prompt。产物仍暴露 Markdown 双 marker 和结构化业务字段占位，分别登记 BC-004、BC-005；BC-004 已通过确定性展示层修复。

同日完成 BC-005 qwen-plus Golden passed 回归：5 次物理调用、14782 Token、99.23 秒、1 次业务修订恢复，最终 68 项验证零错误。Evidence、Claim、Citation、Entity Field Support 和 Action/Risk Entity Recall 均为 100%；Owner P/R 100%，Due Date P/R 100%/50%，Mitigation Recall 0%。剩余跨 Evidence 字段召回登记为 BC-014。

随后执行 BC-014 Prompt 回归：Risk Mitigation P/R 提升至 100%/100%，但 Action Recall 降至 75%、Due Date Recall 降至 33.33%，Risk Precision 为 66.67%、Risk Owner Precision 为 50%。这证明单纯堆 Prompt 会发生指标迁移。

独立 EntityBuilder 的第二次 qwen-plus 实验回归最终 failed：Action Precision/Recall 50%/100%，Risk Precision/Recall 100%/50%，字段支持率 52.38%，30861 Token、169.24 秒。问题登记 BC-015；EntityBuilder 现由 `--entity-projection` 实验开关控制且默认关闭，主路径不会使用未通过 Golden 的策略。

2026-07-16 已完成 BC-015 第二阶段：Action 候选必须无损进入实体，Risk 候选只能 selected 或登记为有文本重合的 duplicate，非候选与不完整裁决 fail closed；无依据字段降级并计入 Trace。保存的真实 Snapshot 可生成 4 个 Action、3 个 Risk 候选。

同日完成两次候选门禁真实回归。lossless candidate Run 用 12915 Token、75.92 秒、无修订，Action/Risk Recall 100%，但 pending Issue 导致 Action Precision 66.67%。canonical candidate Run 用 14636 Token、84.41 秒、无修订，Risk P/R 100%，但专用 Action Evidence 被合并导致 Action Recall 75%，且阻塞依赖被误填 mitigation，Mitigation Precision 50%。两项问题分别登记 BC-016、BC-017，已完成第一版离线修复，当前 191 passed。
