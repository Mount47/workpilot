# 文档维护规则

## 真值优先级

```text
代码与自动化测试
> 可重复运行产物与评测报告
> 已接受设计记录
> 总体设计与实现文档
> 开发计划与状态汇总
```

## 更新时机

- 开始新功能：更新开发清单，建立追加式设计记录；
- 改变公共接口：更新总体设计和实现细节；
- 完成功能：补齐测试、验收结果并标记 ✅；
- 发现问题：更新工程问题；
- 每个阶段结束：更新当前实现状态和 README；
- 指标变化：由评测报告产生，不手工猜测。

## 完成状态规则

- 只有代码存在但未接入主链路：🚧；
- 只在文档中规划：⬜；
- 主链路、失败行为和核心测试齐全：✅；
- 明确不在当前范围或被依赖阻塞：⛔。

## 内容要求

- 说明当前行为，不只说明理想行为；
- 记录输入、输出、错误、重试和边界；
- 避免重复复制代码；
- 链接到对应模块和设计记录；
- 空白占位文档在开发开始前必须补齐；
- 删除或替代设计时保留决策原因。
